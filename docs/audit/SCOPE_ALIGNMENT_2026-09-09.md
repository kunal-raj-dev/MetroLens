# Scope alignment — 9 September 2026

The current application is a single-image packaging screening prototype. The security and correctness fixes improve that working slice; they do not complete the full multi-panel, physical metrology, officer review, or cryptographic dossier requirements. Passing repository governance scripts does not establish legal correctness, measurement accuracy, or production readiness.

This report describes the working-tree source inspected on 9 September 2026. It distinguishes source inspection from tests actually executed. It does not claim a fresh browser, camera, deployed API, disconnected-network, physical calibration, or real-package accuracy test. Concurrent changes must be checked against the cited implementation before using this report as a release record.

Documentation links and the OCR/panel safeguards row were reconciled against current source on 10 September 2026. This did not repeat the recorded verifier or rule test runs.

## Requirement basis

- [MVP_SCOPE](../00_PROJECT_CHARTER/MVP_SCOPE.md): guided capture, quality gate, reference calibration, multilingual OCR, seven-field extraction, Rule 6/7 checks, human review, and PDF/JSON dossier export.
- [SCOPE](../00_PROJECT_CHARTER/SCOPE.md): multi-panel capture, PDP geometry, manufacture-date rule selection, four rule outcomes, and evidence with officer review logs.
- [NON_GOALS](../00_PROJECT_CHARTER/NON_GOALS.md): no autonomous enforcement, uncalibrated physical claims, fake government integration, LLM legal adjudication, or automatic admissibility claims.
- [Functional requirements](../03_PRODUCT_REQUIREMENTS/FUNCTIONAL_REQUIREMENTS.md), [non-functional requirements](../03_PRODUCT_REQUIREMENTS/NON_FUNCTIONAL_REQUIREMENTS.md), [error-state requirements](../03_PRODUCT_REQUIREMENTS/ERROR_STATE_REQUIREMENTS.md), and [acceptance criteria](../03_PRODUCT_REQUIREMENTS/ACCEPTANCE_CRITERIA.md).

“Implemented/hardened” below describes the specified narrow behavior. “Partial” means only part of the requirement is connected. “Gap” means the required capability is not established in the active path. A module or fixture existing on disk is not evidence that the user-facing flow invokes it.

## Legal-source and acceptance limitations

[regulations/source_registry.yaml](../../regulations/source_registry.yaml) marks the relevant USP source `PARTIALLY_VERIFIED`, with `instrument_status: UNKNOWN` and `document_sha256: PRIMARY_SOURCE_REQUIRED`. The [human rule catalog](../02_LEGAL_AUTHORITY/VERIFIED_RULE_CATALOG/rule_catalog.yaml) marks its referenced rules non-executable. The [epoch file](../02_LEGAL_AUTHORITY/VERIFIED_RULE_CATALOG/effective_dates.yaml) gives December 2022 while the legacy USP module header cites October 2022. The historical correction uses the provisional epoch only as a reason to defer judgment. It does not certify either commencement date.

The deterministic Python checks are not driven by a fully verified, version-selected rule registry. Therefore FR-06.1 and the unverified-provision error-state gate are not satisfied merely because rule registry structure passes. Existing statute wording, exemptions, and numerical tables should be treated as reviewable implementation assumptions until reconciled with verified primary sources. This report did not fetch or independently authenticate external law.

AC-03 also needs reconciliation: it cites consumer care as Rule 6(1)(n), while current code/test records use Rule 6(1)(g). Its whole-package omission assertion must be separated from a declaration simply absent from the single photographed panel. No citation or expected verdict was invented to close that discrepancy.

### Internal batch helper follow-up — 10 September 2026

The unused [batch helper](../../apps/api/services/batch_processor.py) still passed a removed production mock-fixture argument and therefore rejected otherwise valid archive members. It now invokes the current real pipeline signature; synthetic responses are injected only in [batch tests](../../tests/integration/test_batch_processor.py). No batch endpoint was added. Review, exemption, and potential-non-compliance states retain separate counts. Failed rule groups come from the returned assessment, and the unsupported fixed ₹25,000 penalty estimate was removed. Its legacy numeric penalty field remains zero with an explicit `compounding_estimate_available: false` flag.

Archive members now have a 15 MiB per-image read limit as well as the existing total-output, entry-count, and compression-ratio limits, plus a compressed archive size cap. Reads use the checked `ZipInfo` object; duplicate names cannot substitute a different member during filename lookup. Cross-platform absolute/traversal paths and duplicate image names are rejected. This is bounded in-memory batch processing, not a claim of streaming upload support or unlimited throughput.

Before the fix, the expanded batch regressions produced **12 failures and 5 passes**, including the removed-argument failure. After the fix, **260 tests passed** across the rules-engine and shared package suites, rule tests, spool unit/security tests, batch tests, and the rules-to-shared-contract mapping test. A final targeted run after count-aggregation and mapping-expectation corrections passed **23 tests** (22 batch tests plus one mapping test). Both green runs had two third-party deprecation warnings. The mapping fixture now preserves missing calibration and an inconclusive overall result. All runs used unique workspace-local spool and temporary directories. These batch tests do not establish real OCR availability, accuracy, or an exposed batch product capability.
